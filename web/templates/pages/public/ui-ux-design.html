01 / UI & UX

Make difficult workflows feel simpler.

Good UX is not about adding more interface. It is about removing uncertainty between what someone wants to do and what the product asks them to do next.

01

Information architecture

Organising content, navigation and page structure so people can find what they need without learning your internal model first.

02

User flows

Mapping the decisions, actions and states that connect a user's goal to a successful outcome.

03

Interface design

Responsive layouts, components and interaction patterns designed around clarity rather than decoration.

04

Design systems

Reusable tokens, patterns and states that keep a growing product coherent and easier to maintain.

02 / Approach

Start with the decision.

I work backwards from what the user needs to understand or accomplish, then shape the information and interface around that outcome.

Research

Find the friction.

Understand users, constraints and the points where the current experience creates hesitation or confusion.

Structure

Clarify the path.

Prioritise information and actions so the interface reflects the user's mental model rather than the organisation chart.

Iteration

Refine with evidence.

Treat the first design as a hypothesis and improve it as behaviour, content and technical constraints become clearer.

03 / System thinking

Consistency without rigidity.

A design system should make the right decisions easier without forcing every problem into the same component.

Tokens

Shared foundations

Colour, type, spacing, radius and motion expressed consistently.

Components

Reusable patterns

Common interface behaviours that stay predictable across the product.

States

Clear feedback

Hover, focus, loading, empty and error states treated as part of the experience.

Accessibility

Built into the system

Keyboard use, contrast, semantics and readable interaction patterns considered from the start.

04 / Process

Understand, shape, test, refine.

The process stays deliberately lightweight so effort goes into solving the product problem rather than producing design theatre.

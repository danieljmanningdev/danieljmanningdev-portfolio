Case study / 2026

Portfolio & Client Workspace

A portfolio designed as more than a marketing page: a fast public site paired with a secure private workspace for managing clients, projects and commercial agreements.

Go HTMX Tailwind CSS SQLite Product Design

01 / The problem

One system for the public story and the private client relationship.

A normal portfolio can show finished work, but it does little to support the relationship once a client actually starts working with you.

The goal was to create a lightweight foundation where client records, projects and contracts live together, without introducing the complexity of a large SPA or rebuilding operational tools that already exist elsewhere.

02 / Product approach

01

Public portfolio

A responsive server-rendered public site focused on product design, engineering capability and selected work.

02

Admin workspace

A private workspace for managing clients, projects, contracts and the relationships between them.

03

Secure foundation

Authentication, server-side sessions, CSRF protection, throttling and security middleware were treated as product requirements rather than afterthoughts.

03 / Architecture

Small layers with clear responsibilities.

HTTP request

↓

security + request middleware

↓

handler

↓

repository

↓

SQLite

↓

Go model + template

↓

HTML response

Business and persistence logic stay out of the HTTP layer. The application remains easy to reason about while retaining enough structure to grow without turning every feature into a framework exercise.

04 / Core functionality

Clients

Client records

Create, view, edit and manage client relationships from a dedicated private workspace.

Projects

Project tracking

Projects belong to clients and carry lifecycle states, dates and descriptions without duplicating task systems.

Contracts

Commercial records

Contracts remain attached to the correct client and can optionally reference that client's project.

05 / Security

Protecting the private workspace.

bcrypt password hashing

server-side hashed sessions

login and logout CSRF protection

login attempt throttling

cross-origin request protection

secure cookie controls

security response headers

authenticated no-store responses

06 / Engineering choices

Deliberately lightweight.

Server-rendered Go

HTML is rendered on the server instead of shipping a large JavaScript application for screens that do not need one.

HTMX where interaction adds value

Focused interactions remain lightweight while the application keeps ordinary browser behaviour and server-side routing.

SQLite as the foundation

The application stays operationally simple while retaining relational constraints, migrations and a tested repository layer.

07 / Result

A portfolio that also demonstrates how I build products.

The result is a working product rather than a static mockup: a public-facing portfolio backed by a tested, authenticated client-management system that can continue evolving as real client requirements emerge.
